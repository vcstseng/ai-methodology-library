試行與交付

試行成果怎麼交付、審查並接回原有流程？

說清成果格式、所需佐證、審查責任及審查未通過時如何退回。

可參考的做法

2 個方法

  • 交付變更與查核證據

    GitHub Agentic Workflows 的人工審查與合併

    如果 AI 交付的是系統變更，可以參考 GitHub 的做法，把變更提案、原始任務、檢查結果和審查紀錄留在同一個流程。由另一位有權的人覆核，待審查通過再接進既有版本。

  • 草稿先經確認再進正式紀錄

    NHS 的 AI 草稿覆核與入檔

    如果 AI 交付的是要進既有系統的文件，可以參考 NHS 的做法：AI 先產生草稿，負責人核對和修改，確認內容後才放進正式紀錄。對企業流程而言，仍要先說明誰能放行，以及草稿不合格時如何處理。

適用範圍

兩個案例的正式交付點不同。本站用它們對照「提案或草稿 → 人工覆核 → 正式紀錄」，實際退回、重做和核准條件要按原流程訂定。
