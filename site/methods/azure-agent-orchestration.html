Azure 的多 agent 協作模式

按工作的依賴關係選循序、平行或動態交接。

原作者怎麼做

  • 按前後依賴安排循序流程。可獨立處理的部分可以平行，再由指定角色匯整。
  • 只傳接手者需要的資訊。需要跨回合持續工作時，把必要狀態存在可恢復的位置。
  • 驗證交接輸出並定義失敗與衝突的處理方式，再決定是否繼續。

為什麼收在這一題

適合比較不同協作模式。模式能幫忙安排工作流，仍需要為個別任務設驗收、合併及權限規則。
