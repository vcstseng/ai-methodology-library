GitHub Spec Kit 的 Spec-Driven Development

從需求規格、技術計畫、任務到實作檢查，沿用同一份交付依據。

原作者怎麼做

  • 先描述需求、使用者行為及成功條件。
  • 把規格轉成技術計畫和可實作的任務，再進行實作。
  • 用 converge 檢查實作是否符合規格、計畫和任務。

為什麼收在這一題

可參考其把任務要求轉為可核對文件的做法。具體命令與文件約定依版本而異。
