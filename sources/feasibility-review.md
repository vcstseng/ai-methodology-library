# 選題與可行性｜六題來源審閱

查核日期為 2026-11-09。下表區分原始指引、研究、實作與本庫的應用判斷。

| 問題 | 候選做法與收錄理由 | 證據界線 |
| --- | --- | --- |
| 選哪個場景 | GOV.UK 說明如何檢查需求和資料，再搭配既有 Jagged Technological Frontier 條目的任務對照。 | 顧問實驗支持按任務驗證的理由，效果數字取決於實驗情境。 |
| 資料和知識 | ODI 補資料集、詮釋資料與基礎設施的準備度，既有 KCS 條目補知識擷取和維護。 | 兩者處理不同缺口。尚未成文的工作判斷要請實際操作者確認。 |
| 系統整合 | GOV.UK 用於盤點技術相依和支援安排，Azure 的概念驗證用於實際測試。既有 AWS 安全重試條目留在回寫設計題。 | 讀取、回寫及權限失敗是本庫的測試例子。概念驗證結果取決於測試環境。 |
| 總成本 | 澳洲政府架構提供生命週期成本，FinOps Foundation 補用量估算，GAO 稽核用於說明可能漏列的成本。 | 稽核是單一案例。審查與培訓工時用企業自己的費率和使用量估算。 |
| 買、組合或自建 | 新加坡 IMDA 說明現成和自建方案所需投入，GOV.UK 補重用與混合取得方式，沿用選題的同一條目。 | 同一工作情境和驗收條件是本庫的比較建議。替代和退場可另查營運與演進。 |
| 出資與成果責任 | Deloitte 章程範例補預算、決策和協作，沿用 Microsoft Agent CoE 的角色責任補成果與營運分工。 | 原文面向組織計畫。用於單一試行時，可只保留此案需要的角色與決策。 |

方法頁各自附上原文及其支持範圍。成本題區分試行前預估、試行後每件合格成果的實際成本，以及上線後的日常監控。
