# 營運與演進｜七題來源審閱
查核日期：2026-11-09。網站條目為有來源的整理；下列比較是編輯判斷。

| 問題 | 比較的候選來源與取捨 | 證據界線 |
| --- | --- | --- |
| 試行怎麼轉日常 | [LGA](https://www2.local.gov.uk/publications/playbook-agentic-ai-local-government) 直接談 agent 的有限試行、正式採用和責任，列為主參考。[Copilot Champions](https://adoption.microsoft.com/en-us/copilot/?role=ai-champions) 補同儕支援。[GOV.UK Beta → Live](https://www.gov.uk/service-manual/agile-delivery/how-the-live-phase-works) 有交接和指標細節，原情境為數位服務，列為延伸。 | 指引描述做法，未提供通用回顧頻率。Microsoft 發布的採用案例未隔離 Champions 的成效。 |
| 誰維護、培訓與接手 | [Microsoft 角色與責任](https://learn.microsoft.com/en-us/agents/center-of-excellence/roles-responsibilities) 明列營運、培訓和服務責任。[AWS Runbooks](https://docs.aws.amazon.com/wellarchitected/2023-04-10/framework/ops_ready_to_support_use_runbooks.html) 明確要求他人實際操作手冊。[Google SRE](https://sre.google/sre-book/evolving-sre-engagement-model/) 的交接更完整，偏向正式技術團隊，放在延伸。 | 三者主要是原始指引或自身做法。一次演練只涵蓋被演練的工作及情境。 |
| 不願用或不再檢查 | [Microsoft Enablement](https://learn.microsoft.com/en-us/agents/center-of-excellence/enablement-community) 與 Champions 的同儕支援重疊，補進既有條目。[HMRC 試行評估](https://www.gov.uk/government/publications/evaluation-report-phase-3-trial-of-microsoft-copilot/evaluating-the-impact-of-microsoft-copilot-in-hmrc) 用作採用障礙紀錄。[UK AI Playbook](https://www.gov.uk/government/publications/ai-playbook-for-the-uk-government/artificial-intelligence-playbook-for-the-uk-government-html#principle-4-you-have-meaningful-human-control-at-the-right-stages) 作為人工控制主指引，[NIST Measure](https://airc.nist.gov/airmf-resources/playbook/measure/) 補監督紀錄。另看過[認知強制研究](https://www.iis.seas.harvard.edu/papers/2021/bucinca2021trust.shtml)，其實驗結果留作後續評估，沒有用它推定企業日常抽查有效。 | HMRC 評估未單獨測試 Champions；人工覆寫與回報量只是監督訊號。 |
| 日常 token 用量與異常 | [FinOps Anomaly Management](https://www.finops.org/framework/capabilities/anomaly-management/) 比 [Usage Optimization](https://www.finops.org/framework/capabilities/usage-optimization/) 更直接回答告警歸屬和調查責任。[OpenTelemetry GenAI](https://github.com/open-telemetry/semantic-conventions-genai) 補個別調用追蹤。 | 規格和示範說明能記錄什麼；重試是否都有記錄及實際費用仍需另核對。 |
| 擴大使用與新團隊重驗 | [Microsoft 分批擴大](https://learn.microsoft.com/en-us/azure/cloud-adoption-framework/ai-agents/integrate-manage-operate) 說明如何決定下一批。[NIST Measure 2.3](https://airc.nist.gov/airmf-resources/playbook/measure/) 補新情境重驗。Microsoft 組織準備指引偏角色與治理，列為配套。 | 無跨情境通用門檻；工作量、資料及覆核安排是本站對照的變數。 |
| 能力改變與流程重設 | [Anthropic Evals](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) 回答新舊能力怎麼比；[Workflow／Agent 選擇](https://www.anthropic.com/research/building-effective-agents) 回答自主性的取捨。[Context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) 偏模型如何取用上下文，未列主條目。 | 供應商工程實務與案例，測試通過無法單獨驗證人機交接設計。 |
| 供應商退場與備援 | [DDaT Playbook](https://www.gov.uk/government/publications/the-digital-data-and-technology-playbook/the-digital-data-and-technology-playbook#exit-planning) 比雲端鎖定指引更直接涵蓋交接責任與服務銜接。[AI Risk Management Toolkit](https://www.gov.uk/government/publications/ai-risk-management-toolkit/ai-risk-management-toolkit-guidance) 補突然失效時的營運持續。 | 政府指引未驗證企業特定產品的匯出能力、切換結果或恢復時間。 |
